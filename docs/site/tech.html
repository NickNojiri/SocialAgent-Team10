SpotBot reference

SpotBot is a Discord bot that turns the Instagram and TikTok reels your friends share into places you actually go. Paste a reel: it reads the caption, the audio and the text on the video, works out the place, and posts a card the server votes on. At three votes it's on the calendar.

This page documents every part of it. Capture, commands and buttons are what users touch; the system section covers the web pages, the APIs, the pipeline and the settings behind them. CSULB CECS 491A, Team 10.

Capture

paste a link

capture · any channel or DM
https://www.instagram.com/reel/… or https://www.tiktok.com/@…/video/…

No command. Paste one or more public Instagram or TikTok links. SpotBot reacts with ⏳, replies with what it is doing, and edits that reply into a spot card in about 20–45 seconds. In a DM the spot goes to your private list instead of the server's.

Where it listens

Every channel it can read, unless /setup picked one reels channel, and never in a channel turned off with /mute.

Commands

/setup

command · Manage Server
/setup

Someone with Manage Server gets a private three-step form: (1) the reels channel, or every channel, or Create #spot-drops; (2) the home city, used for distances on cards; (3) Save. Re-running it changes only what you change. Everyone else sees a 20-second explainer and the current settings.

See also: GET/PUT /api/settings · /mute

/plan

command
/plan

Reads the last 25 messages (not kept), sums up the vibe, area, budget and time it heard, opens a thread and posts the best saved spots as votable cards. A spot named in the chat is 📌 pinned; "I'm in Irvine", or two people in different places, sorts picks by distance or by the midpoint. Keep chatting and run it again to refine.

See also: POST /plan · /events

/events

command
/events vibe:<text>
vibe
What you're in the mood for, e.g. late night tacos.

Searches this server's saved spots by meaning (embeddings), not just words.

See also: POST /recommend · /browse

/browse

command
/browse [category:<kind>] [area:<text>] [when:<dated|undated>]
category
One of the categories, everything, or 💭 not a place.
area
Only spots in this area; suggests this server's areas as you type.
when
📅 has a date, or 🗓️ no date yet.

A numbered, page-by-page list sorted by votes, with ◀ ▶ to turn pages.

/catalog

command
/catalog

The leaderboard: top-voted spots grouped by kind, with not-a-place reels in a quiet 💭 section at the end.

See also: /digest

/digest

command
/digest

One message: spot count, nights out, the top three spots, and how many are still waiting for a plan.

/share

command
/share

A link to this server's spots as a web page anyone can view. The link carries a read-only signed token, so it can't vote, delete, or show another server. Changing the signing key revokes every link.

/app

command · prototype (ADR-0008)
/app

A personal link, visible only to you, to the SpotBot phone app at :8010/app: your spots with a Restaurants filter, add a reel by link (or from Android's share sheet once installed), and an event page per spot with Going / Maybe / Can't, a find a time poll and Invite friends, a link anyone can RSVP from without Discord. The link holds a guest token and one signed for you; neither can delete, forget or change settings.

See also: POST /api/events/{id}/rsvp · /poll · /api/invite

/privacy

command · Manage Server to delete
/privacy

What's saved (spots, votes with display names, settings, capture history, anonymous feedback), what isn't (your chat; audio is deleted once transcribed), where it goes, who can see it, and Delete all of this data…, confirmed by typing the server name. In a DM it deletes your own list.

See also: POST /api/forget

/feedback

command
/feedback kind:<bug|idea>

bug or idea; opens a short form.

Saved without your name.

/survey

command
/survey [participant:<code>]
participant
The code from the researcher, e.g. P3 (optional).

The System Usability Scale: 10 statements, tap 1–5. Scores are kept without names; the team reads the count, mean and SD.

/mute

Admin API (src/ingestion/serving/admin.py, :8010)

Every request that names a guild_id must carry X-Tenant-Token, an HMAC token for that server; read scope is enough for reads, full scope for writes, and votes are signed for the voting user. A guest token (invite links) reads and may RSVP or vote in a poll, nothing else.

Pipeline (src/ingestion/pipeline/orchestrator.py)

stagewhat it doesmodule
1 fetchHeadless Chromium renders the page; an embed-page fallback handles login walls; optional logged-in pathbrowser/
2 extractJSON-LD and Open Graph tags, then per-site selectorsextractors/
3 listen · readfaster-whisper turns audio into text; RapidOCR reads on-screen text (both optional)transcriber.py, ocr.py
4 normalizeRule parser picks venue, category and city, each with a confidencenormalizer.py
5 time"this Friday 8pm" → a real datetemporal_resolver.py
6 validateStrict Pydantic record; platform boilerplate is never a venuevalidator.py
7 storeJSONL log (source of truth) + ChromaDB, one collection per serversinks/

Failure messages (app/cards.py FAILURE_MESSAGES)

classwhat the user sees
private🔒 That reel is private or needs a login, so I can't read it.
removed🚫 That post is gone — it was deleted, or the link is wrong.
timeout⏱️ The site took too long to answer. Retry — it usually works the second time.
network📶 I couldn't reach the site just now.
unsupported🔗 I can only read public Instagram and TikTok links.
too_slow⏱️ That one took too long to read (a long video?).
no_text🤷 I couldn't find a caption, spoken words or on-screen text to go on.
not_a_place🤔 That post doesn't look like it's about a place, an event or food.
past_event📅 That event has already happened, so I didn't save it.
no_venue🔎 I read it, but couldn't tell which place it's about.
bug😵 Something broke on our side.

deliveryDocker Compose, GitHub Actions

Security

rulehow
tenant isolationEach server's data is reached only with an HMAC token for that server; keys rotate with a grace period
no pingsEvery message is sent with mentions disabled, so a pasted @everyone pings nobody
local-firstCaptions and audio are read on the host; no paid APIs, no post text sent off the machine
safe fetchingOnly public http(s) links; internal addresses refused (SSRF tests)
